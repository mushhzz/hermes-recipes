## Interpretation rules

- Distinguish **actual internal deployments**, **vendor methodology**, **randomized workplace assistance experiments**, and **industry survey associations**. They support different conclusions.
- Generated code, merged PRs, survey usefulness, model non-reproduction, estimated labor savings and delivered production outcomes are not interchangeable metrics.
- AWS method guidance does not prove a deployed autonomous lifecycle. Amazon internal modernization and the attributed Mantle anecdote are separately labeled.
- The Microsoft-linked sources are versions of one pooled study, not additional independent replications. DORA summaries do not substitute for the full report's statistical methods.
- Recommendations from prior research are marked inferences and preserved for provenance. The architecture document describes the selected contract; it does not silently adopt every prior suggestion.
- Only distilled research and short excerpts are archived, not full source-page mirrors. No credentials are included.

## Implementation and verification status

The Python background controller is installed in the local Hermes setup; Hermes and GitHub are its user interfaces, with no lifecycle executable or package main entrypoint. The service retains the supervisor name `hermes-sdlc`. Historical authenticated receiver, Docker checks, recovery regressions and real-model evaluation results remain preserved. They do not establish live end-to-end verification of the post-cutover GitHub workflow. Publication stays disabled until a dedicated bot and repository policy are configured; external deployment and Loki integration also require real configuration. A contract, an accepted HTTP request and completed production verification remain different evidence.
